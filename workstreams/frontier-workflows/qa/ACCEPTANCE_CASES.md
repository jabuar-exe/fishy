# Frontier release QA acceptance cases

Run existing 19 scene tests unchanged before these release checks. Use the current browser scene as authority; a native review export is evidence only unless it is a valid browser proposal.

| ID | Action | Pass condition |
| --- | --- | --- |
| P1 | Open every addable catalog entry and inspect its material preview, then Add it. | Each of the 19 addable entries has a genuine rendered procedural preview from the same descriptor and `makeObject` path as Add. Preview form, added form, color, and kind agree. Juniper is visibly reference-only and cannot Add. |
| P2 | Add one material, record its object ID, then replace/apply a compatible material. | Add creates exactly one new ID. Apply preserves that ID, transform, size, stretch, color and protection unless explicitly changed; it never creates a duplicate. |
| T1 | Drag each tank dimension slider through several values and Undo once. | Each completed drag creates one revision/history entry. Undo restores all pre-drag scene state; Redo restores the final value. |
| T2 | Start a tank slider gesture, alter the value, then Escape. Repeat with exact input. | The original dimension and source are restored, no history entry is added, and selection/focus behavior remains stable. |
| T3 | Apply a tank preset that would force a protected object outside bounds. | The preset is rejected atomically: no axis, object, revision, source or history state changes. A fitting preset commits all three dimensions in one history entry. |
| A1 | Manually move, rotate, resize, or change shape of an unprotected object. | The successful edit auto-protects that object, visibly marks it protected, and groups the requested edit/protection outcome according to the documented history behavior. Explicit release removes protection only when selected by the user. |
| A2 | Trigger a stale slider/transform commit after another edit changes the revision. | The stale result cannot overwrite current scene state; the active control returns to canonical data and explains the cancellation. |
| R1 | Import a browser proposal that modifies/deletes current protected fields while also changing an unlocked field. | Review shows raw attempted changes and blocked attempts. Effective proposal preserves trusted protected fields, validates containment after merge, and does not silently accept deletion. |
| R2 | Try Apply for a proposal with mismatched scene ID/base revision, then a same-scene/current-revision proposal. | Mismatched proposal is blocked before mutation. Current proposal requires review before Apply, commits once, and Undo restores the exact pre-apply browser scene in one step. Proposal revision never controls the committed revision. |
| N1 | Import a valid native-runtime artifact containing changes and evaluation data. | It is labelled imported/native and view-only; it cannot offer browser Apply or mutate the browser scene. No artifact path/URL is fetched. |
| N2 | Inspect an evaluation record with a complete score and one with pending/no scores. | Scores identify native series/revision/recipe/camera/mask hashes only, retain fixture/validation/strict-test status, and are never presented as browser-scene accuracy. Missing data is explicit. |
| N3 | Attach a local photo response to a pending native request, then repeat with `baseRevision` set to the imported run's input revision. | The response carries the imported **run.revision** (the accepted state being answered), not `run.baseRevision`; run/scene/request/view/object/hash/photo-name mismatches are rejected. It records only “awaiting native revision,” leaving the imported review immutable. |
| S1 | Save a scene with changed controls, protection state, draft-free proposal history, and undo/redo state; reload. | Current scene and supported saved history restore without loss or changed IDs. Invalid/pending controls block Save; corrupt storage fails closed and remains untouched. |
| M1 | At 200% zoom and narrow width, complete Tank → Materials → Arrange → Ideas → proposal review using keyboard. | Every task has a labelled reachable trigger, visible focus, no hidden focus target, and sheets return focus to their trigger. Escape cancels active adjustment before clearing selection/closing a panel. |

## Pure regression candidates when interfaces arrive

1. Validate all 19 catalog descriptors map to a preview and Add descriptor generated by one shared factory; assert Juniper has no Add route.
2. Exercise proposal parsing with: protected-field mutation, protected deletion, stale base revision, current same-scene proposal, native-runtime proposal, invalid citations, and evaluation score identity fields.
3. Exercise atomic preset/resize behavior and explicit protection transitions through exported pure helpers; do not mirror React gesture internals in unit tests.

## Release blockers

- A preview that is not generated from the Add descriptor/factory.
- More than one history entry per completed continuous gesture, or Escape committing state.
- A protected current-browser field changed/deleted by an imported proposal, a stale proposal applying, or a native proposal gaining Apply.
- Evaluation UI associating native score/metric with browser geometry or hiding a missing-data/fixture state.

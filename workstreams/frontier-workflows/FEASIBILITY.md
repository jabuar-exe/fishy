Existing native exports are **not recipe imports**: `fishy.blender.scene.v1.position_m` is an object's origin, while recipe positions are base-centres. Export preserves shear via the full matrix but does not preserve mesh topology. Blindly reusing its AABB as pre-yaw size would double-rotate or distort objects. `build_recipe.py` tags objects with `tank_id`, `fishy_recipe_asset`, `fishy_recipe_seed`, and original `fishy_recipe_item_json`, which makes a restricted transform adapter feasible.

## Shared state decisions before implementation

1. Retain existing `manifest.json` as run authority instead of introducing a competing `run.json`. Add lineage ID, accepted revision, base revision, builder hash, input registry and workflow statuses. Store immutable proposal, effective recipe, snapshot, diffs, logs and score artifacts in each run. A lineage can expose revision-indexed artifacts without overwriting old runs.
2. Recipe `revision` should echo the **base** revision in a model proposal. After compare-and-swap succeeds, the trusted acceptance layer creates revision `base + 1`. Record both fields explicitly; the model must never mint the accepted revision. Lock/compare snapshot hash at application time to reject edits made while the request was running.
3. `protected[]` is trusted application state. A model cannot remove protection by returning an empty list. Only explicit human release changes it. New human edits automatically union into that set; model deletion/asset/seed/size/transform changes are blocked and logged.
4. Use stable photo IDs backed by immutable SHA256/source/view/role records. Observations reference registered reconstruction photos only; object evidence references existing observation IDs. Regions must be finite and satisfy `0 <= x0 < x1 <= 1` and `0 <= y0 < y1 <= 1`. No evidence means `inferred: true`; render its review marker separately from evaluation masks.
5. Preserve raw model output before any merge. Perform structural/type checks on the proposal, then protected-state enforcement, then complete geometry validation of the effective scene. A proposed protected object outside the tank should be logged as an attempted override, rather than defeating the protection demonstration before enforcement. Invalid unprotected geometry remains a rejection.

## W3: feasible first, with explicit native boundaries

The minimal reliable native path is: capture current scene and protection metadata in the running Blender process; save a **copy** to the new run (never save over the user's file); dispatch a background revision with that snapshot; use trusted current values in the model prompt; merge returned unprotected changes; build a new scene; preserve protected object data and matrices from the snapshot; verify and open the separate result. The human's unsaved driftwood position must be captured before any subprocess reads a file.

For the two-hour scope, support the existing constrained translation/yaw/scale controls using original procedural asset metadata and a validated effective recipe. Explicitly reject unsupported shear, tilt, arbitrary mesh topology or unsupported modifiers before a request if the builder cannot preserve them. Alternatively, append protected object datablocks from the snapshot `.blend` and verify their mesh digest/matrix separately; this preserves native shape but requires verifier changes beyond a recipe-only merge. Do not claim arbitrary native edits survive if only transforms do.

A depsgraph handler alone sees both human and programmatic updates and may emit hundreds of drag samples. Keep a transform baseline and coalesce/flush committed changes on revision/export, with timestamp, base revision, source and explicit programmatic suppression. Undo must restore the authoritative current position even if the event log retains historical movement. Flush final snapshot to avoid a race with the last drag. Explicit Release Protection persists across revisions.

Acceptance fixtures: attempted move, rotation, resize, asset/seed replacement and deletion of protected wood are blocked; missing/duplicate protected IDs fail closed; release permits a later edit; stale snapshots fail; a reported rock fix requires an actual non-protected diff. Runtime check compares actual built world matrix translation within 0.001 m, orientation within 1 degree, scale/shape digest unchanged, and full stable ID set. Equality of recipe fields alone is insufficient.

## W1: feasible extension; a real unanswered-photo run needs more evidence

`--revise-run` currently **rejects `--image`**, and only carries prior role=`reference` files plus `front.png`/`overview.png`. Add a dedicated `--answer-request` / `--answer-photo` registration path, validate view tag against the pending request, keep the existing no-automatic-retry behavior, and pass only allowed reconstruction inputs to the model.

Require at most two ranked uncertainties with existing object IDs and views `front`, `left`, `right`, `top` or `close_up:<valid existing ID>`. Persist a request ID tied to the revision and object. A supplied photo may satisfy one explicit pending request; no silent relabeling. Diff accepted recipes and save per-field changes, model-space displacement in cm, and cited new observation IDs. A model citation demonstrates a recorded explanation, not independently verified visual causation.

Resolve the document's contradiction: W1 step 5 says any no-change result is unresolved, but its confirming-photo fixture correctly requires no move. Use `resolved_changed`, `resolved_confirmed`, and `request_unresolved`. A confirming response needs a new observation citation and an explicit explanation; unchanged contradictory evidence stays unresolved. The live demo's requested-photo-to-movement acceptance remains separate from the confirming fixture. Deterministic mock fixtures test the protocol; only a real model run establishes that Astra used the supplied view.

## W2: implementation is possible; honest live score is input-limited

The inspected saved model runs all reference the same file hash `d55daecba77708fa09c719a997d53035b1ea8436188694414a26e8734004364a`, the 280 × 210 `facebook_fishtank_photos/final_candidates/07334576064f0460.jpg`. Runs `20260913T004310Z-6e2dabec`, `20260913T004455Z-72721c2e`, and `20260913T010130Z-2653bd9e` therefore do not provide multiple real views. The revision's additional images are its own renders. Imported run `20260913T032710Z-9fc5c2f7` has no source images. The existing 106 final candidates and collection manifests do not establish same-tank identity or a linked multi-view capture; no verified second real view was found in the scoped metadata. Do not treat different aquarium photographs, synthetic renders, or generated views as independent evidence.

Inputs needed for real acceptance: 3–5 real views of one unchanged tank, known/declared-assumed dimensions, one held-out view chosen before reconstruction, one extra reconstruction view available to answer the request, a fixed held-out camera/calibration record, manually verified visible hardscape mask and per-object masks/centroids, image resolution, mask policy and frozen metric configuration. If these cannot be supplied, ship explicit `not_evaluated` with the missing inputs and separately labeled synthetic scoring fixtures; do not invent a before/after number.

Four tank corners alone are not an unconditional camera solve: if coplanar they constrain a planar homography, not general depth and unknown intrinsics. Fix intrinsics/assumptions or manually match a perspective camera; prefer additional known non-coplanar box corners. Store pose, focal/intrinsic assumptions, reprojection residual and limitations once. Existing `fit_camera()` is an orthographic aesthetic framing helper, not real-photo calibration. Freeze the camera, masks, renderer and builder across revisions; do not refit each revision to improve its score.

Primary metric remains visible-hardscape silhouette IoU, fixed before a run. Use foreground union of rock/wood IDs, excluding plants, tank, floor, captions and inference markers under a documented occlusion rule. Add masked SSIM with a fixed range/window and visible-object centroid errors; LPIPS need not be added for this timebox. Require matching dimensions, nonempty masks and explicit missing-object penalties/status. Render object-ID masks with the same camera/visibility, not by thresholding beauty material colors. Include photo/mask/camera/recipe/builder hashes and evaluation version in score JSON. Report regressions honestly.

Isolation must occur at the final transport image loader for both Codex `--image` and API byte encoding. Resolve paths under the allowed reconstruction/render roots and validate registered IDs/roles/hashes; reject traversal, symlinks outside the root, held-out files renamed into reconstruction roles and duplicate hashes across splits. Do not pass the complete run manifest, scores, overlays, held-out camera screenshot, mask, or score-informed next-step hints into the model prompt. Selecting later changes after seeing repeated held-out scores is evaluation feedback leakage even if the photo bytes are hidden; freeze the revision policy and reveal final results only after the sequence, or describe the view as validation rather than a strict test set.

## Browser/native integration boundary

This scout did not edit `site/`. The current native generator is a local CLI/subprocess workflow, not a hosted API or automatic browser bridge. The browser owner must expose whether the UI is operating a local fixture, imported recorded run, or a live model job. Do not make a browser button appear to have launched Blender/model generation unless the bridge actually exists.

Existing genuine meshes are available at `design-lab/blender/runs/20260913-110819/{hero-60-arch,panorama-90-angular,cube-45-stump}/aquarium.glb` and `hardscape.glb`. `design-lab/blender/build_showcase.py` exports selected geometry, extras and Y-up GLBs; `verify_glb.py` checks GLB IDs/bounds. These are authored procedural showcase scenes, not multi-view reconstruction evidence. Their IDs (`fishy_id`, containing periods) and centered coordinates differ from recipe `tank_id` IDs and front-left-bottom coordinates; adapters must map IDs/axes/units explicitly, never guess by label.

For individual previews/sliders, extract or expose actual source object geometry by stable ID and apply numeric transforms to that geometry. Report whether a slider scales an envelope or regenerates shape parameters. Reuse real asset exports; CSS perspective or a stack of stills does not establish an editable 3D preview. A recorded frontier artifact bundle should provide lineage/revision, source label, effective objects, observations, request status, edit log, protection result and scoring availability to the browser without exposing held-out data to generation.
